## 4. THE LOOP — what the docs agent actually does, and what it cannot do

Each pass: run `tools/audit_graph.py`; read every participant tree read-only for new commits and
packets; verify claims against the artefacts rather than against the claiming agent's summary;
update `agents.tsv` motions and `blocked_on`; land verdicts in `docs/consults/`; update §2's
state column; and **tell Chad who is worth waking next.**

**The honest limitation: agents run only when Chad starts them.** There is no daemon. The loop
cannot make anyone work — it observes, verifies, records, and sequences. What it removes is
Chad having to know whose turn it is or carry any content between trees.

**Standing verification rule for this loop:** a claim from an agent is a claim. Check the
artefact. This has already paid twice in one day — the v2 archive's `sha256` matched when
checked, and the `EvCTAPE` schema probe read `v2` off a comment before it was re-anchored.
